18  Figure composition and saving

NoteLearning outcomes & Chapter summary
  1. Compose plots into horizontal, vertical, and nested layouts.
  2. Choose panel sizes, shared axes, titles, and labels to support comparisons.
  3. Save figures in suitable static or interactive formats, including self-contained offline HTML.

18.1 Why bother?

A single plot may not answer every part of a question. Combining complementary views can show a relationship alongside its distributions, or let readers compare how the same response relates to different predictors. The layout should make those comparisons easier, rather than simply fit more plots onto a page.

After composing a figure, we also need to choose how to share it. A PNG is convenient in a document, a vector image stays sharp when resized, and an HTML file can preserve browser interactions. We introduce the export workflow here, then develop the interactions themselves in Interactivity.

18.2 Preparing complementary panels

We will reuse the cars dataset. We keep observations with recorded fuel economy, horsepower, and weight so that both panels show the same cars. If a variable is shared between panels, placing it on the same axis makes the relationships easier to compare. Here, weight stays on the y-axis. The short titles identify panels while we experiment with layouts; for a communication figure, a title explaining the message may be more useful.

  • Altair
  • ggplot
import altair as alt
import pandas as pd

cars = pd.read_csv('data/vega-cars.csv').dropna(
    subset=['Miles_per_Gallon', 'Horsepower', 'Weight_in_lbs', 'Origin']
)
mpg_weight = alt.Chart(cars, title='Fuel economy and weight').mark_point().encode(
    x='Miles_per_Gallon:Q', y='Weight_in_lbs:Q', color='Origin:N'
)
hp_weight = alt.Chart(cars, title='Horsepower and weight').mark_point().encode(
    x='Horsepower:Q', y='Weight_in_lbs:Q', color='Origin:N'
)
mpg_weight
hp_weight
library(tidyverse)
library(patchwork)

cars <- read_csv('data/vega-cars.csv') |>
    drop_na(Miles_per_Gallon, Horsepower, Weight_in_lbs, Origin)
mpg_weight <- ggplot(cars, aes(x = Miles_per_Gallon, y = Weight_in_lbs, color = Origin)) +
    geom_point() + labs(title = 'Fuel economy and weight')
hp_weight <- ggplot(cars, aes(x = Horsepower, y = Weight_in_lbs, color = Origin)) +
    geom_point() + labs(title = 'Horsepower and weight')
mpg_weight
hp_weight

18.3 Arranging panels horizontally and vertically

Side-by-side panels

  • Altair
  • ggplot

Use the pipe operator, |, for horizontal concatenation. Set the dimensions of the individual panels before composing them. Here the two x-axes represent different measurements, but the y-axis represents weight in both panels, so we explicitly share its scale.

mpg_weight = mpg_weight.properties(width=250, height=220)
hp_weight = hp_weight.properties(width=250, height=220)
(mpg_weight | hp_weight).resolve_scale(y='shared')

patchwork composes ggplot objects with layout operators. As in Altair, | places panels side by side.

mpg_weight | hp_weight

Patchwork aligns panel geometry automatically, but each ggplot retains its own scales. These panels use the same cars and y-variable, so their default y-ranges agree. When data or scale settings differ, specify common limits if direct comparison requires them.

Stacked panels

  • Altair
  • ggplot

Use & for vertical concatenation.

mpg_weight & hp_weight

Use / to stack panels vertically. This differs from Altair’s & operator.

mpg_weight / hp_weight

In patchwork, & instead applies a setting to every panel. For example, (mpg_weight / hp_weight) & theme(legend.position = 'none') hides both legends.

Overall titles and panel labels

  • Altair
  • ggplot

Parentheses make it clear that properties() applies to the composed figure, not just the second panel.

(mpg_weight | hp_weight).properties(title='Two views of vehicle weight')

The functions alt.hconcat() and alt.vconcat() are alternatives to | and &. For example, the following also adds an overall title:

alt.hconcat(mpg_weight, hp_weight, title='Two views of vehicle weight')

plot_annotation(tag_levels = 'A') adds automatic panel tags A, B, and so on. Use tag_levels = list(c('A', 'B')) to supply an explicit sequence of tags.

(mpg_weight | hp_weight) + plot_annotation(tag_levels = 'A')

The same function adds an overall title to the composed figure. Here we also collect the matching legends into a single guide.

(mpg_weight | hp_weight) +
    plot_layout(guides = 'collect') +
    plot_annotation(
        title = 'Two views of vehicle weight',
        tag_levels = 'A',
        theme = theme(plot.title = element_text(face = 'bold'))
    )

guides = 'collect' consolidates matching legends. It does not make different color scales equivalent, so check that shared colors retain the same meaning.

18.4 Unequal widths and nested layouts

Complementary panels do not always need equal space. A scatterplot may need a wide plotting area, while a categorical count chart can remain readable in a narrower panel.

  • Altair
  • ggplot

A short histogram can show the distribution of fuel economy, and a narrow strip of ticks can show weights within each origin.

mpg_hist = alt.Chart(cars).mark_bar().encode(
    x=alt.X('Miles_per_Gallon:Q').bin(), y='count()'
).properties(width=250, height=80)
mpg_hist
weight_ticks = alt.Chart(cars).mark_tick().encode(
    x='Origin:N', y='Weight_in_lbs:Q', color='Origin:N'
).properties(width=90, height=220)
mpg_weight | weight_ticks

Combining operators without parentheses may produce a different arrangement than intended. Python evaluates & before |, so this puts the histogram above the scatterplot and then places the tick plot alongside that entire column:

mpg_hist & mpg_weight | weight_ticks

Parentheses can instead group the scatterplot and ticks into the bottom row:

mpg_hist & (mpg_weight | weight_ticks)

Check which axes should align when arranging marginal distributions. The histogram’s x-variable matches the scatterplot’s x-variable, and the tick plot’s y-variable matches the scatterplot’s y-variable. Sharing a variable does not make every possible arrangement equally easy to read.

First create a count chart of origins. This is a categorical summary of the same cars, rather than a marginal distribution of either scatterplot axis.

origin_count <- ggplot(cars, aes(x = Origin)) + geom_bar()
origin_count

An equally wide panel can give a three-category count chart more space than it needs. plot_layout(widths = c(3, 1)) allocates three times as much panel width to the scatterplot. Axes, titles, and legends need additional space, so the full plot widths need not have exactly that ratio.

mpg_weight | origin_count
(mpg_weight | origin_count) + plot_layout(widths = c(3, 1))

Here the scatterplot legend falls between the panels. Reordering them keeps that legend at the outside edge:

(origin_count | mpg_weight) + plot_layout(widths = c(1, 3))

We can also nest layouts with parentheses and control the relative heights of rows. This deliberately repeats the count plot to make the layout structure easy to see. Automatic tags continue through the nested panels.

top_row <- origin_count | origin_count
nested_figure <- (top_row / mpg_weight) +
    plot_layout(heights = c(1, 2)) +
    plot_annotation(title = 'Vehicle weight and sample composition', tag_levels = 'A')
nested_figure

18.5 Choosing an output format

Format Useful for What to consider
PNG Slides, documents, previews Raster image: enlarging it reveals pixels; choose sufficient resolution
SVG or PDF Resizable diagrams and publication figures Vector output stays sharp, but dense plots can create large files
HTML Interactive charts Preserves supported browser interactions; decide whether dependencies and data must work offline

Saving a static image preserves the displayed view, not its tooltips, selections, or controls. Exporting a notebook or book page is also different from saving an individual figure.

18.6 Saving static figures

The following save commands are intended to be run when you want to create files; they are not executed automatically while rendering this chapter.

  • Altair
  • ggplot

The filename extension selects the output format. PNG, SVG, and PDF export use vl-convert-python, included in the textbook environment through Altair’s optional dependencies.

mpg_weight.save('mpg_weight.png')
mpg_weight.save('mpg_weight.svg')
mpg_weight.save('mpg_weight.pdf')

scale_factor scales the exported image dimensions. For example, this produces three times as many pixels along each dimension of a PNG:

mpg_weight.save('mpg_weight-hires.png', scale_factor=3)

Altair also offers ppi for specifying PNG pixel density. The chart’s width and height determine its layout; exporting more pixels does not automatically make small labels proportionally larger within the figure.

mpg_weight.save('mpg_weight-print.png', ppi=300)
mpg_weight.save('mpg_weight.json')

ggsave() can save the most recent plot when its plot argument is omitted. Passing the object explicitly avoids accidentally exporting a different plot. Specify physical size and pixel density when preparing a raster image.

ggsave('mpg_weight-r.png', plot = mpg_weight, width = 6, height = 4, units = 'in', dpi = 300)

At six by four inches, 300 dpi produces a 1,800 by 1,200 pixel image. Using 96 dpi at the same size gives fewer pixels, not a higher-resolution image. Vector formats do not use dpi to determine the resolution of their vector elements. SVG export uses the svglite package.

ggsave('mpg_weight-r.pdf', plot = mpg_weight, width = 6, height = 4)
ggsave('mpg_weight-r.svg', plot = mpg_weight, width = 6, height = 4)

The plot argument can also be a composed patchwork figure:

ggsave('vehicle-layout.svg', plot = nested_figure, width = 6, height = 7)

18.7 Saving interactive figures, including offline HTML

Altair: include both the data and JavaScript

This chart has tooltips and supports panning and zooming. Its data comes from a local dataframe, so Altair embeds the values in the specification.

interactive_cars = mpg_weight.encode(
    tooltip=['Name:N', 'Origin:N', 'Horsepower:Q', 'Miles_per_Gallon:Q']
).interactive()
interactive_cars

Saving HTML preserves these client-side interactions: the recipient does not need a running Python process or Jupyter session. However, the default HTML export loads JavaScript libraries from an online CDN.

interactive_cars.save('cars-interactive.html')

For an HTML file that can be opened without an internet connection, use inline=True. It bundles the JavaScript dependencies into the file, making it larger but self-contained for this dataframe-based example.

interactive_cars.save('cars-interactive-offline.html', inline=True)

inline=True bundles the rendering libraries; it does not automatically download arbitrary externally referenced datasets, map tiles, or images. For example, a chart built with a data URL may still need the network to retrieve its data. Load the data into a dataframe before constructing the chart, as we do here, and check the exported file with the network disabled.

You can send the resulting HTML file as an attachment or host it on a static website such as GitHub Pages. Naming it index.html makes it the usual landing page for its directory. The lecture’s Altair demos provide examples of this kind of sharing. For integration into a larger report, interactive_cars.to_html(inline=True) returns the HTML as a string instead of writing a file.

R: save the HTML widget

Wrapping a ggplot in plotly::ggplotly() creates an interactive HTML widget. This preview has hover details, zooming, and a clickable legend; we will explore those interactions in Interactivity.

interactive_cars_r <- plotly::ggplotly(mpg_weight)
interactive_cars_r

Use htmlwidgets::saveWidget() to preserve the widget’s interactivity.

htmlwidgets::saveWidget(interactive_cars_r, 'cars-interactive-r.html', selfcontained = TRUE)

selfcontained = TRUE bundles local widget dependencies into one HTML file, using Pandoc. It is suitable for this chart, whose data is included in the widget. As with Altair, externally requested resources such as online map tiles still need their own offline solution. For a multi-file export, use selfcontained = FALSE and distribute the accompanying dependency directory together with the HTML.

An HTML page containing widgets plus other elements, such as headings or filter controls, is a container rather than one HTML widget. Save the container with htmltools::save_html(), then bundle its local dependencies with rmarkdown::pandoc_self_contained_html():

widget_page <- htmltools::tagList(
    htmltools::tags$head(htmltools::tags$title('Vehicle explorer')),
    htmltools::h2('Vehicle explorer'), interactive_cars_r
)
htmltools::save_html(widget_page, 'vehicle-page.html', libdir = 'vehicle-page_files')
rmarkdown::pandoc_self_contained_html('vehicle-page.html', 'vehicle-page-offline.html')

The final file includes the local widget dependencies; the intermediate HTML and dependency directory are useful if you prefer a multi-file website. This is the same workflow we will use for a page of linked plots and controls in Interactivity.

18.8 Notebook display formats and static previews

A notebook can store several representations of one output, such as a Vega-Lite specification, HTML, and a PNG. The viewer chooses which representation it can display. GitHub’s notebook viewer does not run arbitrary interactive JavaScript, so a chart that works in JupyterLab may need a static fallback there.

In a compatible Jupyter frontend, Altair’s MIME renderer supplies a Vega-Lite representation that the frontend can render and may save with a PNG fallback:

alt.renderers.enable('mimetype')

Run the plotting cells again and save the notebook so the outputs are stored. The frontend must support the chart’s Vega-Lite version; the Python MIME bundle alone does not guarantee that a PNG has been stored. For an explicitly static notebook output, use the PNG renderer instead:

alt.renderers.enable('png')
mpg_weight

Return to interactive HTML display with alt.renderers.enable('default'). A PNG fallback is a static preview; sharing the HTML export preserves interactive exploration. Notebook display settings and exported-file formats are separate choices.
